# FlowBench API (Phase 4)

Read-only, no-auth FastAPI service over `warehouse.*` — see
[docs/SPEC.md §5](../docs/SPEC.md#5-api-surface) for the endpoint list and
[docs/SPEC.md §1](../docs/SPEC.md#1-locked-decisions) for why (no writes,
no PII, no reason to gate it).

## Run locally

```
pip install -r api/requirements.txt
uvicorn api.main:app --reload
```

Then open `http://127.0.0.1:8000/docs` for interactive Swagger docs
(auto-generated by FastAPI from `api/schemas.py`).

## Endpoints

- `GET /stations` — paginated station list (`limit`, `offset`)
- `GET /stations/{id}/demand?range=` — hourly demand curve for one
  station; `range` is a lookback window in days from the end of the
  warehouse's date range (omit for the full window)
- `GET /network/demand` — system-wide hourly demand curve (used by the
  dashboard's Trends page)
- `GET /network/imbalance?hour=` — every station's average net balance
  at a given hour-of-day (0–23), ascending (most-depleted first)
- `GET /insights/weekday-vs-weekend` — the query 4 result, computed live
  (Shapiro-Wilk picks Welch's-t vs. Mann-Whitney, same as
  `analysis/q04_weekday_vs_weekend.py`)
- `GET /insights/rebalancing-candidates?limit=&bikes_per_truck_hour=` —
  the query 8 ranking, with the truck-capacity assumption exposed as a
  query param instead of hardcoded

## Tests

```
pip install -r api/requirements-dev.txt
pytest api/tests
```

Tests run against a small, disposable `flowbench_test` database (3
stations, 14 days, ~130 trips) created and torn down by
`api/tests/conftest.py` — never the real dev warehouse. Requires the same
local Postgres the rest of the project uses (`docker-compose up`).

## Performance

Three endpoints originally recomputed a heavy aggregate over all 45.7M
`fact_trips`/11.8M `station_hourly_balance` rows on every request; all
three are now backed by a materialized rollup refreshed once per
warehouse build (`warehouse/migrations/0004-0007_*.sql`) instead:

| Endpoint | Before | After |
|---|---|---|
| `GET /network/imbalance?hour=` | ~668ms | ~1.5ms |
| `GET /insights/rebalancing-candidates` | ~46s | ~30ms |
| `GET /insights/weekday-vs-weekend` | ~5.9s | ~35ms |

See [docs/RESULTS.md](../docs/RESULTS.md#performance) for the full
`EXPLAIN ANALYZE` before/after on the first of these.
